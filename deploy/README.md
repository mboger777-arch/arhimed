# Выкладка АРХИМЕД MVP

> Перед началом работы над кодом прочитай `deploy/ИНСТРУКЦИЯ_ДЛЯ_ИИ.md` — это вход в проект
> для нового агента (карта файлов, устройство уроков, форматы данных, проверки, грабли).
> Текущее состояние и очередь задач — в `deploy/СОСТОЯНИЕ.md`.

Приложение живёт на сервере в `/opt/arhimed`, код берётся **из GitHub** (ветка `main`
репозитория `alenamissia-source/arhimed`). Ничего вручную на сервер копировать не нужно —
достаточно запушить изменения и выполнить выкладку.

## Что должно быть на сервере

| Что | Где | Кто создаёт |
|---|---|---|
| Каталог приложения | `/opt/arhimed` | скрипт выкладки |
| Виртуальное окружение с `aiohttp` | `/opt/arhimed/venv` | скрипт выкладки (сохраняет прежнее) |
| `systemd`-сервис | `arhimed` | настраивается один раз вручную |
| Ключ Яндекс-API | `/opt/arhimed/ключ_яндекса.txt` | лежит только на сервере, в репозиторий не попадает |

## Запуск

```bash
PYTHONPATH=.py-libs python3 deploy/deploy.py
```

Скрипт скачает архив ветки `main`, развернёт его в `/opt`, **сохранит** ключ и `venv`,
перезапустит сервис и проверит, что сайт отвечает и что на нём та самая версия
(`v=NNN`), которая лежит в локальном `MVP/index.html`.

## Где взять доступы

Пароли в репозитории не хранятся. Скрипт ищет их по порядку:

1. переменные окружения `ARH_HOST`, `ARH_USER`, `ARH_PASS`;
2. файл `deploy/deploy.local.env` (он в `.gitignore`):

   ```
   ARH_HOST=адрес-сервера
   ARH_USER=пользователь
   ARH_PASS=пароль
   ```

3. файл `~/.arhimed_deploy` с тем же форматом.

Если доступов нет, скрипт ничего не делает и подсказывает, чего не хватает.

## Полезные переменные (необязательные)

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ARH_REPO` | `alenamissia-source/arhimed` | репозиторий-источник |
| `ARH_BRANCH` | `main` | ветка |
| `ARH_SITE` | `https://123.teramont.pro/MVP/` | адрес для проверки |
| `ARH_SERVICE` | `arhimed` | имя systemd-сервиса |
| `ARH_ROOT` / `ARH_APP` | `/opt` / `arhimed` | каталоги на сервере |

## Приложение родителя и коды детей

Второе приложение (только вкладка «Родитель») живёт по адресу
`https://123.teramont.pro/MVP/родитель/`. Ребёнок при первом входе в общее
приложение получает код вида `ARH-XXXX-XX` (вкладка «Родитель» в детском
приложении). Родитель вводит этот код и придумывает PIN из 4 цифр — после этого
видит отчёт, может задать лимит занятий на день и оставить заметку ребёнку.

Технически это делает шлюз `шлюз_сервер.py`, маршрут `/api/kid`:

| Действие | Кто вызывает | Что делает |
|---|---|---|
| `new` | детское приложение | создаёт код и ключ устройства |
| `probe` | приложение родителя | говорит, задан ли уже PIN родителя и привязано ли устройство |
| `device` | детское приложение | ребёнок задаёт **свой** PIN — устройство привязывается |
| `enter` | детское приложение | вход по PIN ребёнка |
| `rebind` | детское приложение | привязка заново своим PIN после отвязки |
| `sync` | детское приложение | снимок прогресса (только для привязанного устройства) |
| `take` | детское приложение | лимит и заметки родителя |
| `claim` | приложение родителя | первый вход: родитель задаёт **свой** PIN |
| `get` | приложение родителя | отчёт (код + PIN родителя) |
| `set` | приложение родителя | лимит и заметка |
| `unlink` | приложение родителя | отвязывает устройство ребёнка (свой PIN остаётся) |
| `delparent` | приложение родителя | удаляет аккаунт родителя: PIN, лимит, заметки, отчёт + отвязка |

PIN ребёнка и PIN родителя — разные, оба хранятся только хешем (sha256 с солью).
После 8 неверных попыток вход по соответствующему PIN блокируется на 10 минут.
Привязка живёт на устройстве: после отвязки ребёнок вводит свой PIN заново
(`rebind`) или создаёт новый код, прогресс на устройстве при этом сохраняется.

Данные лежат **вне** каталога приложения — в `/opt/arhimed-data/kids`, поэтому
выкладка (она заменяет `/opt/arhimed` целиком) их не удаляет. Каталог создаётся
скриптом выкладки; путь можно переопределить переменной `ARH_DATA`.
PIN хранится только в виде хеша (sha256 с солью), после 8 неверных попыток вход
по коду блокируется на 10 минут.

## Проверки раскладки уроков

Перед выкладкой полезно прогнать гейт раскладки — он ловит наложения текста,
обрезку за контейнер, схлопнутые сцены и сдвиг от центра:

```bash
PYTHONPATH=.py-libs python3 qa_layout.py 97 98 99 108 51 96
```

Скрипт поднимает локальный сервер (`http://127.0.0.1:8123`) — запусти его заранее:

```bash
cd MVP && python3 -m http.server 8123 &
```

## Откат

Прежняя версия остаётся на сервере в `/opt/arhimed_old` до следующей выкладки.
Если новая сборка сломалась, вернуть прежнюю можно так:

```bash
# на сервере
rm -rf /opt/arhimed && mv /opt/arhimed_old /opt/arhimed && systemctl restart arhimed
```

## Русский язык (с v519)

- Предмет добавляется полем `subj:'rus'` в уроке; список предметов — `SUBJ_META` в `MVP/js/lessons.js`,
  порядок табов — массив `order` там же. Класс для фильтра берётся из `src` («Русский язык · 5–6 класс · …»).
- Уроки: `MVP/data/vis_ru.js`, id 601–610, по 9 шагов. Все сцены рисуются SVG-помощниками `RUKIT`
  (надстройка над `PKIT` из `vis_pw.js`): плашки слов, морфемы, рамки-правила. Картинок и видео нет — только рисунок.
- Остров «Русский язык» объявлен в `ISLANDS` (`MVP/js/app.js`), диапазон классов для его задач — в карте `R`
  функции `taskClassRange`. Задачи лежат в `MVP/data/tasks_ru.js` (30 штук, id `rus1…rus30`),
  тема обязательно начинается с класса («5 класс · …»), иначе фильтр по классу не сработает.
- Оба файла подключены в `MVP/index.html` после `data/tasks.js` и `data/vis_pw.js`.
- Проверка раскладки: `PYTHONPATH=.py-libs python3 qa_layout.py 601 602 … 610` (гейт ловит обрезание,
  наложение текста, пустую сцену и сдвиг центра; меряет листовые элементы, служебный CSS игнорирует).
